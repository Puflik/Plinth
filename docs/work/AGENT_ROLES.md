# Модели и effort в Plinth

Решение автора от 2026-11-04: сохранить разделение исследователя и
исполнителей из Claude, выбирать модель и effort по задаче; Terra участвует.
Это рабочее распределение ролей, а не измеренная эквивалентность моделей.

| Работа | Модель | Effort | Настроенный агент |
|---|---|---|---|
| Исследование, архитектура, независимое ревью | `gpt-6-astra` | `xhigh` | `plinth_researcher` |
| Исследование, план и ревью CRDT, журнала, миграций, восстановления | `gpt-6-astra` | `max` | `plinth_data_reviewer` |
| Файл задачи и защищённые тесты по принятому решению | `gpt-6.1-sol` | `xhigh` | `plinth_planner` |
| Rust, бизнес-логика, обычная реализация по плану | `gpt-6.1-sol` | `high` | `plinth_executor` |
| UI, проверка экранов, локальная правка с ясной приёмкой | `gpt-6.1-terra` | `high` | `plinth_ui_executor` |
| Небольшая однозначная правка, сверка, документация | `gpt-6-luna` | `medium` | `plinth_light_executor` |
| Семантическое извлечение ограниченного фрагмента для графа | `gpt-6-luna` | `high` | `plinth_graph` |

Основной координатор по умолчанию — Astra `xhigh`; обычный неназванный
исполнитель — Sol `high`. Astra исследует и принимает решение, исполнитель
работает по файлу задачи, Astra проверяет результат. Планировщик и исполнитель
разделены; автор реализации не выдаёт себе итоговое независимое ревью.
Для данных пользователя исследование решения ведёт Astra `max`, Sol `xhigh`
оформляет принятое решение и тесты, затем Astra `max` проверяет план до кода.

## Когда менять effort или модель

- Механическая сверка или перенос готового текста: Luna `low`.
- Небольшая правка экрана без нового поведения: Terra `medium`.
- Сложная конкурентность, сквозной FFI, трудное воспроизведение сбоя:
  Sol `xhigh`; неопределённое решение сначала исследует Astra.
- Сохранность пользовательских данных: Astra `max` исследует решение,
  читает план до кода и проверяет результат. Это не делает каждый вызов
  исполнителя `max`.
- Если задача Luna требует нового решения или выходит за список файлов,
  она пишет вопрос; координатор передаёт задачу Sol/Terra либо Astra.
  Увеличение effort не заменяет недостающие требования или тесты.
- Terra подходит для экрана и ограниченной правки; один только язык Kotlin
  не делает сложную задачу о данных задачей Terra. Проверка интерфейса
  остаётся у Terra, а инварианты журнала — у Astra.

Эти уровни — исходная настройка. Менять их по результатам реальных задач:
приёмка, пропущенные ошибки, число кругов ревью и расход окна. `ultra` не
включается по умолчанию. Сравнения стоимости токена API не заменяют замер
расхода подписки Codex.

## Как настройки применяются

Общие значения находятся в `.codex/config.toml`, именованные роли — в
`.codex/agents/*.toml`. Проект должен быть доверенным. Выбор модели в уже
открытом чате и явные параметры запуска могут иметь больший приоритет;
изменение файла не доказывает переключение текущего чата.

Когда инструмент поддерживает именованную роль, использовать её. В текущем
интерфейсе `collaboration.spawn_agent` роль задаётся заданием, а модель и effort
передаются явно: `fork_turns="none"`, `model`, `reasoning_effort`. Полную историю
не пересылать: передать роль, путь к файлу задачи и разрешённый объём работы.
Именованный профиль фиксирует effort; для другого уровня использовать явный
запуск без этого профиля, чтобы файл профиля не переопределил уровень.

Перед каждым новым агентом — `get_usage_limits`; запускать по одному.
В проектной конфигурации одновременно разрешён один подагент. При ≥65%
пятичасового или ≥85% недельного окна новый не запускается; неизвестный
расход не считать нулём. Суточный бюджет считать до фактического `resetsAt`.
Не открывать новый пользовательский чат вместо подагента без просьбы автора.

В файле задачи записывать запланированные и фактически использованные модель
и effort для каждого этапа. Если модель недоступна, явно зафиксировать замену;
не выдавать запуск другой модели за выполненный прежней.

Основания выбора: официальные [рекомендации по моделям](https://developers.openai.com/api/docs/guides/model-selection)
описывают Astra для глубокого анализа, Sol для сложной технической работы,
Terra для визуальной работы и ограниченных исправлений, Luna для узких задач.
Формат настройки — [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)
и [проектная конфигурация](https://learn.chatgpt.com/docs/config-file/config-basic).
