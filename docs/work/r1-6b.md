## Цель

Лайки, подписки и чёрный список держат «добавление побеждает параллельное удаление»
(ADR 0007) при любой истории установок, а не только при общей: защищённый тест Р1.6
`sets_stay_add_wins_a_like_removed_on_the_new_installation_returns` перестаёт падать в
2–3 % прогонов. Журналы прошлых версий читаются.

## Контекст

Множества лежат в плоских картах `yrs` (`likes`, `subscriptions`, `blocks`) под ключом
без установки: `<TrackId>`, `<ArtistId>`, `track:<id>` / `artist:<id>`. Две установки с
разной историей — новая и восстановленная копия старой — добавили один ключ порознь:
обе вставки без левого соседа, и `yrs` оставляет за ключом вставку с **большим** номером
клиента (проверено; номер — случайные 53 бита на каждое `Journal::open`). Если это та,
что потом снята, добавление из копии пропадает. Сломан и ADR 0007: «добавление побеждает»
держалось только при общей истории. В эталоне `registers-legacy` номер клиента лайка —
около 0,974 диапазона, поэтому защищённый тест падал в 2–3 % прогонов.

Р1.6 развела регистры: у каждой установки свой слот `ключ@<DeviceId>`, ключ без суффикса —
слот журнала до Р1.6. Вся машинерия в `doc.rs` уже есть; множества её не используют.

отсутствующего — `false`, операция в журнал и в базу не идёт.

## Решение

**Слот на установку — и у множеств.** Элемент множества с id `K` (ключ, каким он был) хранится
слотами: `K@<DeviceId>` — добавление этой установки — и `K` без суффикса — слот журнала до
Р1.6б (читается, новым кодом не пишется). Установка пишет только свой слот, поэтому
параллельных вставок одного ключа нет и `yrs` ничего не разводит по номеру клиента.

1. **Добавление** (`Like`, `Subscribe`, `Block`): у элемента уже есть слот — любой: свой,
   чужой, без суффикса; читаемый или нет — ничего не делает (`false`, как прежний `add`).
   Иначе пишет слот `K@<своя установка>` с той же записью, что и раньше. Слоты ищет проба
   ключей по суффиксам установок карты (`open` + `has_slot`), без прохода по карте на каждую
   операцию.
2. **Снятие** (`Unlike`, `Unsubscribe`, `Unblock`): стирает все слоты элемента, которые
   видит, читаемые и нет (`remove_slots`); `true`, если стёрт хоть один. Слот, которого
   снимавшая установка не видела, остаётся: параллельное добавление сильнее снятия.
3. **Чтение** (`state`): элемент есть, если у него есть читаемый слот. Списки — по id, как
   были. `since` у подписки и записи чёрного списка берётся из действующего слота — того
   же, что у регистров: с наибольшим `(meta.at, meta.device)`, при равенстве — по ключу
   (`newest`). Нечитаемый слот пропускается и считается в `unreadable` — каждый один раз,
   даже если у элемента есть читаемый (как у регистров).
4. **Без изменений:** `superseded` (ключ — `DeviceId`, только пополняется, снимать нечего:
   параллельные вставки теряют лишь копию записи, ключ остаётся); `plays`, `decisions`;
   запись `codec`, `OP_SCHEMA` (= 2), файлы `store`, `Op`, `JournalState`, FFI, Kotlin.

```rust
// core/sync/src/journal/doc.rs

// Slots: три новые карты, суффиксы собираются при первом обращении к карте в правке.
struct Slots {
    ratings: Option<Suffixes>,
    playlists: Option<Suffixes>,
    entries: Option<Suffixes>,
    settings: Option<Suffixes>,
    passports: Option<Suffixes>,
    likes: Option<Suffixes>,
    subscriptions: Option<Suffixes>,
    blocks: Option<Suffixes>,
}

/// Добавляет элемент множества `id` слотом установки `meta.device`; `false` — у элемента
/// уже есть слот: свой, чужой или журнала до Р1.6б, читаемый или нет.
fn add_member(
    register: Register<'_>,
    txn: &mut TransactionMut,
    id: &str,
    meta: &OpMeta,
    record: impl FnOnce() -> Vec<u8>,
) -> bool {
    if has_slot(register, txn, id) {
        return false;
    }
    put(register.map, txn, own_key(id, meta.device), record())
}

// write_one: Like (так же Subscribe, Block — с их ключами и записями)
Op::Like { track } => {
    let found = open(&self.likes, &mut slots.likes, txn, meta.device);
    add_member(found, txn, &track.to_string(), meta, || encode(meta, |_| ()))
}
Op::Unlike { track } => {
    let found = open(&self.likes, &mut slots.likes, txn, meta.device);
    remove_slots(found, txn, &track.to_string())
}

// state: те же `registers`, что у остальных; id приходит без суффикса.
state.likes = registers(&self.likes, txn, &mut skip, |id, value| {
    let (meta, ()) = slot(value, |_| Ok(()))?;
    Ok((meta, id.parse()?))
});
state.subscriptions = registers(&self.subscriptions, txn, &mut skip, |id, value| {
    let artist = id.parse()?;
    let (meta, since) = slot(value, |r| r.since())?;
    Ok((meta, Subscription { artist, since }))
});
state.blocklist = registers(&self.blocks, txn, &mut skip, |id, value| {
    let target = block_target(id)?;
    let (meta, since) = slot(value, |r| r.since())?;
    Ok((meta, BlockEntry { target, since }))
});
```

Фрагменты — рабочий набросок; имена внутренних помощников любые, поведение — по пунктам
выше. `add` остаётся для `superseded`, `keyed` — для `read_superseded`: мёртвого кода быть не
должно (`clippy -D warnings`). Шапка `doc.rs` и комментарий к `registers` описывают то, что
делает код: множества теперь тоже слоты.

Отвергнуто:

- **Править результат слияния по времени.** Проигравшую вставку `yrs` стирает при
  интеграции — сравнивать не с чем (как в Р1.6).
- **Номер клиента `yrs` из времени.** Старый код пишет случайные 53-битные номера — новый
  должен их бить; решает время открытия сессии, а не записи (как в Р1.6).
- **Двойная запись: слот и ключ без суффикса — чтобы 0.2.x видел новые лайки.** Ключ без
  суффикса снова спорил бы по номеру клиента и тащил за собой прежнюю ошибку; снятие обязано
  стирать оба; объём вдвое. Для регистров так не делали — множества не лучше.
- **Метки в значении (множество внутри записи).** Конкурирующую вставку `yrs` всё равно
  отбросит целиком — потеряются и метки.
- **Писать собственный слот и при добавлении элемента, который виден по чужому слоту.**
  Журнал растёт, `false` у `write_one` пропадает, а выигрыша нет: установка добавляет только
  то, чего не видит.

## Инварианты

- Сходимость: после полного обмена у всех реплик одно `JournalState`, в любом порядке
  обмена и при любых номерах клиентов `yrs`.
- Добавление побеждает снятие, которого оно не видело; снятие стирает все слоты, которые
  видело — свои, чужие, без суффикса, читаемые и нет, — и ничего больше.
- Журнал любой прошлой версии читается: ключи без суффикса — слоты (`journal_corpus.rs`, эталон
  `registers-legacy`, тесты `doc.rs` зелёные без правок).
- Повторное добавление имеющегося и снятие отсутствующего журнал не меняют (`false`,
  вектор состояния `yrs` на месте).
- Порядок списков `JournalState` — по id, как был; `unreadable` считает каждый нечитаемый слот.
- Старый код не ломается о новые ключи: ключ `K@<установка>` не разбирается как id —
  пропускается как нечитаемый, документ не портится. Данные, записанные новой версией, для
  него скрыты, но остаются в документе.
- Формат записи, `OP_SCHEMA`, `store`, FFI, Kotlin, схема БД не меняются.
