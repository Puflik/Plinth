# Тестовый APK YouTube из GitHub Actions

## Модели и effort

- План: координатор; отдельный планировщик не запускался.
- Исполнение: Luna medium (фактическая модель/effort исполнителя).

## Цель

После успешной проверки CI сохранять тестовый APK flavor `github`, чтобы автор
мог проверить YouTube на устройстве. Публикации релиза и проверка на устройстве
в эту задачу не входят.

## Менять

- `.github/workflows/ci.yml`
- `docs/work/test-apk.md`
- `docs/testing/test-apk.md` (новый файл)

## План реализации

Добавить в конец успешного check job, перед always-отчётами, один шаг
`actions/upload-artifact@v4`. Имя: `plinth-github-debug-${{ github.sha }}`;
путь: `app/build/outputs/apk/github/debug/*.apk`; срок хранения: 7 дней;
`if-no-files-found: error`. Использовать стандартное условие успеха шага.
Сборки, триггеры, разрешения, зависимости, версии, подпись и код приложения
не менять. Не включать release secrets и не расширять glob.

Добавить краткую инструкцию на русском: snapshot содержит YouTube; debug имеет
отдельный пакет от release; отображаемая версия может оставаться
`0.2.3-debug`; скачать artifact успешного запуска и распаковать APK для
необязательной ручной установки. Не выполнять установку на телефон, adb или
удаление приложений. Релизный тег не создавать.

## Защищённые тесты

Не применимо: добавляется обратимый шаг workflow и документация; тесты и
пользовательские данные не затрагиваются.

## Проверки

- Проверить YAML доступным PyYAML и вручную проверить структуру/условие шага.
- `git diff --check`.
- Убедиться, что diff ограничен тремя файлами и содержит ровно один шаг upload.
- Не запускать Gradle или тесты: CI уже собирает APK.

Контекст: CI main `419ae48`, run `43358730931` успешно завершился. Проверка
API 15 ноября показала один reports artifact (`expired: false`); прежний
workflow APK не сохранял. Новый APK artifact ещё нужно получить из успешного
запуска этой ветки. Устройство и живой YouTube пока
не проверялись.
