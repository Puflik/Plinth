## Проект и границы

Plinth — автономный Android-плеер без центрального сервера. Трек — логическая
сущность с несколькими источниками; модель ядра — `Track → Version → Source`.
Лайки, плейлисты, история и другое пользовательское хранятся в CRDT-журнале;
SQLite — каталог и пересобираемая проекция. Пути, токены и кэш в журнал не идут.

- Android: один модуль `:app`, Kotlin, Compose, Hilt, Media3. Границы пакетов
  проверяют тесты-стражи. UI работает через фасады библиотеки и
  `PlaybackController`; чистые `audio/engine` и `queue` не зависят от Android.
- Rust workspace: `types`, `library`, `sync`, `providers`, `ffi`,
  `uniffi-bindgen`. SQLite, `yrs`, `lofty`; UniFFI поверх JNA.
- Сгенерированные типы и JNA не выходят за Kotlin-пакет `ffi`.
  Ошибки ядра переводятся в ошибки приложения; паники не пересекают FFI.
- Internet Archive реализован в Rust. YouTube — NewPipeExtractor в Kotlin,
  подключённый как `ExternalProvider` через UniFFI; реестр и каталог в ядре.
  Сеть обслуживает платформа. Радио — YouTube Mix.
- Сборки `github` и `fdroid`, minSdk 26, compile/target SDK 37, AGPLv3.
  Выпуски сейчас на GitHub; публикация в F-Droid запланирована позднее.

Подробности: `docs/ARCHITECTURE.md`, `docs/adr/`, `docs/BUILD.md`.
README описывает выпущенную 0.2.3; текущую работу уточнять по `tasks.md`,
`CHANGELOG.md` → Unreleased и последним решениям.

## Как работать

Сохраняется процесс из `docs/work/README.md`: задача в файле → отдельные
падающие тесты → реализация → ревью → проверки → слияние → записи в документах.
Смена инструмента не отменяет защищённые тесты и инварианты.

- Перед реализацией — `docs/work/<id>.md` по шаблону: решение, разрешённые
  файлы, защищённые тесты, команды, критерии и условия остановки.
- Ветки задач — `work/<id>` (CI следит за `work/**`). Действующий путь из
  рабочего процесса — `C:\claude\Plinth-<id>`. Ошибочный путь `C:\Codex\...`
  в перенесённом `AGENTS.md` исправлен; перед созданием сверить реальный worktree.
- В worktree нужны правила агента, локальные настройки и путь к SDK:
  часть из них не появляется из Git автоматически. `AGENTS.md`, настройки
  моделей и `.codex/agents` теперь версионируются; `.agents`, хуки и
  `local.properties` проверять отдельно, не рассчитывать на память другого чата.
- План, затрагивающий данные пользователя, отдельно читается до исполнителя.
  Исполнитель не меняет защищённые тесты и файлы вне списка, не сливает main.
  После падения проверок — одна попытка исправить; повторное падение — отчёт.
- Ревью проверяет неизменность тестов относительно их коммита, разрешённые
  файлы, CI, обрыв/повтор/пустые и повреждённые входы. Только затем слияние.
- Названия Opus/Sonnet/Haiku описывают прежний состав. По следующему запросу
  автора назначены Astra (исследование/ревью), Sol (логика/Rust), Terra
  (UI/ограниченные правки), Luna (простое/граф). Effort и фактические параметры
  — `AGENT_ROLES.md`; не заявлять, что недоступная модель запускалась.
- Коммиты и обычный fast-forward push ранее разрешены автором; перед ними
  `git diff --check`, подходящие проверки и просмотр состава изменений.
  Текст коммита — файлом через `git commit -F`, без атрибуции ИИ.
  Теги, выпуск и переписывание опубликованной истории — по явному слову автора.
- Пуш через локальный прокси автора запрещён его прежним решением. Нет прямой
  сети — работа и коммиты остаются локально до восстановления связи.
- В чат — краткий итог и необходимые вопросы. Подробности — в файл задачи.
  Требования и ответы автора дописывать в `docs/decisions.md`.

## Проверки и местная среда

- Gradle запускать из PowerShell с
  `$env:JAVA_HOME = 'C:\Program Files\Android\openjdk\jdk-21.0.8'`.
  Этот JDK существует; системная Java указывает на Java 8. SDK задан в
  `local.properties`. Версии: Rust 1.98.1, Gradle 9.7.1, AGP 9.4.1,
  NDK 28.2.13676358, cargo-ndk 4.1.2; источники — version catalog,
  `core/rust-toolchain.toml`, wrapper, `docs/BUILD.md`.
- Rust из `core/`: `cargo test --workspace --locked`,
  `cargo clippy --workspace --all-targets --locked -- -D warnings`,
  `cargo fmt --all -- --check`. На Windows различать CRLF-шум и реальный diff;
  `--config newline_style=Auto` полезен для локальной проверки, CI остаётся эталоном.
  Не запускать форматирование всего workspace ради одной правки.
- Kotlin: `ktlintCheck`, `detekt`, `testGithubDebugUnitTest`,
  `testFdroidDebugUnitTest`, `lintGithubDebug`; точный набор — по задаче.
  В README процесса записаны семь известных Windows-сбоев DataStore;
  устаревшее число в шаблоне заменено ссылкой на процесс. Это историческая оговорка, не основание игнорировать
  новое падение: сравнивать тот же тест на исходной версии и с Linux CI.
- Инструментальные тесты — на эмуляторе с явно заданным `ANDROID_SERIAL`
  в том же вызове Gradle. Фильтр по пакету надёжнее списка классов с запятыми.
  Перезагрузка телефона — только по слову автора: он раздаёт интернет.
- Не делить `core/target` между worktree. Не обрывать вывод сборки через
  `Select-Object -First`: это может остановить процесс. Сохранять лог, читать после.
  Различать выполненные проверки и `FROM-CACHE`/`UP-TO-DATE`;
  когда нужен новый прогон задачи, использовать её `--rerun`.
