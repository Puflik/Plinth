# 0005. Треки и теги в v0.1 — из `MediaStore`

- **Статус:** принято; действует до v0.2, где библиотеку заменит ядро на Rust.
- **Подробнее:** `tasks-v0.1.md`, раздел C2 (решение C2);
  `docs/decisions.md` — «Вертикаль «локальная библиотека» (эпик C): разбивка на
  шаги», «Шаг 3 вертикали «библиотека»: сканер на `MediaStore`», «Шаг G3:
  ошибки воспроизведения».

## Контекст

Библиотеке v0.1 нужны треки с тегами. Варианта два:

| Вариант | Плюс | Минус |
|---|---|---|
| `MediaStore` | Ноль зависимостей, быстро | Видит только то, что проиндексировал системный сканер |
| Свой обход папок + библиотека тегов | Видит всё | Зависимость, которую выбросит v0.2 |

Весь эпик C (Room, сканер) в v0.2 переписывается под Rust — вкладываться в
него сверх нужного незачем.

## Решение

- Треки и теги берутся из **`MediaStore`**: строки `IS_MUSIC`, папка — от
  корня тома (`RELATIVE_PATH` на Android 10+, из `DATA` на 8–9).
- Скан инкрементальный: сверка `_ID` + `DATE_MODIFIED`; изменённое — `upsert`,
  пропавшее — **помечается `missing`, а не удаляется**; `upsert` того же
  `id` возвращает трек.
- `TagReader` нормализует то, что отдаёт система: `<unknown>` и пустое — нет
  тега, края обрезаются; `TRACK` = диск × 1000 + номер; без названия — имя
  файла без расширения. `album_artist` запрашивается строкой: константа
  открыта с API 30, колонка есть раньше.
- Файл вне библиотеки играет через SAF («Открыть файл») — без разрешения и
  мимо `MediaStore`.

## Последствия

- Файлы, которых системный сканер не видит (вне общего хранилища, в
  немедийных папках), в библиотеку не попадают. Полный обход папок придёт с
  ядром.
- **У файла без тега альбома `MediaStore` ставит альбомом имя папки**, и
  отличить это от настоящего тега нельзя. v0.1 принимает альбом по папке;
  честное «нет альбома» — с ядром, которое читает теги само.
- Пропавший трек скрыт из всех списков, но в очереди остаётся на месте и
  пропускается, когда до него доходит игра. Неоткрывшийся трек библиотеки
  запускает пересканирование, один раз за запуск: помечает пропавшее сканер,
  источник правды — `MediaStore`.
- Поведение на API 26–29 (время сканера, набор тегов, `album_artist`)
  проверено только JVM-тестами: образа эмулятора ниже API 36 нет.
- Экраны видят библиотеку только через фасады `LibraryRepository`,
  `LibraryScan` и `FolderSettings` (страж `LibraryBoundaryTest`) — их и
  переживёт переход на ядро.
