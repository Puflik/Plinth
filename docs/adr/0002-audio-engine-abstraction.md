# 0002. Воспроизведение — за интерфейсом `AudioEngine`

- **Статус:** принято, действует.
- **Подробнее:** `docs/plan/03-architecture.md`, разделы 3.3–3.4;
  `docs/ARCHITECTURE.md` — «Главная граница: `AudioEngine`»;
  `docs/decisions.md` — «Шаг 2 вертикали «звук из файла»: B1 — абстракция
  `AudioEngine`» и «Шаг 3 …: B2 — `Media3Engine`».

## Контекст

Media3 есть только на Android. Воспроизведение понадобится ещё в трёх местах:

- десктопный клиент (v1.5) — там звук даст Rust-движок (Symphonia + cpal);
- «аудиофильский» движок на Rust для Android (R3) — второй движок рядом с
  Media3, а не замена: у Media3 лучше батарея (audio offload) и фон;
- тесты — экраны и очередь не должны требовать эмулятора и звука.

## Решение

- Пакет `audio/engine` — **чистый Kotlin**: интерфейс `AudioEngine`
  (`prepare` · `play` · `pause` · `seekTo` · `setVolume` · `release`),
  `AudioSource`, `PlaybackParams`, `TrackInfo`, состояние (`StateFlow`),
  события (`SharedFlow`, только случившееся после подписки) и типизированные
  ошибки `PlaybackError`. **Ни один тип `androidx.media3` не пересекает эту
  границу.**
- Команды не приостанавливаются: движок принимает их сразу, проверяет
  аргументы в потоке вызывающего и отвечает асинхронно — через состояние и
  события.
- Требования к любой реализации — в коде: `AudioEngineContractTest`. Его
  проходят `Media3Engine` (на эмуляторе) и `FakeAudioEngine` (на JVM).
- `EngineBoundaryTest` читает исходники `audio/engine` и падает на первом же
  импорте Android.
- Экраны управляют звуком только через `PlaybackController` — он же хозяин
  очереди и реакции на ошибки.

## Последствия

- `PlaybackController`, очередь, плеер и экраны библиотеки проверяются на
  `FakeAudioEngine` без эмулятора — это большая часть JVM-тестов проекта.
- Новый движок (десктоп, R3) встаёт на то же место, пройдя тот же контракт;
  переключение движков становится настройкой.
- Цена — лишний слой. Всё, что умеет Media3, приходится выражать в терминах
  движка: подписи трека для системы (`TrackInfo`), следующий трек для gapless
  (`PlaybackParams`), виды ошибок.
- Команды внешних пультов (уведомление, гарнитура) приходят в плеер через
  сессию, мимо движка. Движок их видит, потому что адаптер слушает сам плеер,
  а «следующий/предыдущий» сессия отдаёт в очередь через
  `QueueCommandsPlayer`.
- Каждая команда `prepare` получает номер: запоздавшие сообщения старого
  трека наверх не идут.
