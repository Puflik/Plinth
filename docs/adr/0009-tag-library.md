# 0009. Теги читает `lofty`

- **Статус:** принято 2026-09-25.
- **Подробнее:** `tasks-v0.2.md`, эпик D, D2; `docs/decisions.md` — «D2.1:
  lofty или Symphonia».

## Контекст

С v0.2 теги файлов читает ядро (D2), а не `MediaStore`
([ADR 0005](0005-tag-source-v01.md)). Кандидатов два:

- **`lofty`** — библиотека только тегов: читает и пишет;
- **метаданные Symphonia** — идут в комплекте с декодером, который, возможно,
  понадобится в v0.3 для акустических отпечатков.

Второй вариант экономит зависимость, первый — вероятно, полнее. Решать по
проверке на коллекции автора.

## Решение

- **`lofty` 0.25** — чтение тегов и свойств звука: длительность, битрейт,
  частота, разрядность, кодек внутри MP4. Фича по умолчанию
  (`id3v2_compression_support`, крейт `flate2`) остаётся включённой: без неё
  0.25.4 не собирается.
- **Проверка:** одна и та же выжимка тегов через обе библиотеки. Наборы:
  - коллекция автора — 307 MP3 с диска ПК (FLAC и M4A у автора нет);
  - фикстуры `app/src/androidTest/assets` — 12 файлов, семь форматов;
  - шесть размеченных файлов: FLAC, M4A, Ogg Vorbis, Opus, MP3 с ID3v2.3 и
    ID3v2.4. В каждом — album artist, диск, compilation, кириллица.

  | | lofty 0.25.4 | Symphonia 0.6.1 |
  |---|---|---|
  | Прочитано без ошибок | 325 из 325 | 325 из 325 |
  | Поля на коллекции | — | те же, кроме номера трека в 5 файлах, если свести порядок тегов (ниже) |
  | Битрейт | есть | нет — только считать из размера файла |
  | ALAC и AAC в M4A | различает | различает |
  | Compilation в ID3v2.4 (`TXXX:TCMP`) | читает | не читает |
  | ID3v1 без номера трека | нет номера | номер `0` |
  | Порядок тегов | главный тег файла первым | ID3v1 с конца файла раньше ID3v2 |
  | 307 файлов, тёплый кэш | 29 мс | 40 мс |
  | Цена в `.so`, arm64 | +0,68 МБ | +0,76 МБ (только метаданные) |
  | Запись тегов | есть | нет |
  | Лицензия | MIT или Apache-2.0 | MPL-2.0 |

- **Ловушка Symphonia с ID3v1.** В ID3v1 поле обрезано до 30 байт, а
  кириллица и иероглифы заменены на `?`. Symphonia кладёт этот тег в журнал
  метаданных раньше ID3v2. Кто берёт первый, получает «Yuna ? ?Jinsei Game?
  [???? ? ?» вместо «Yuna – ↑Jinsei Game↓ [Игра в жизнь]». У lofty главный
  тег — ID3v2 — идёт первым сам.
- **Экономии зависимости нет.** Экспорт тегов в файлы и редактор тегов
  (план 13.3, фичи 35–36) требуют записи, а Symphonia только читает. Значит,
  `lofty` в ядре появится в любом случае.

## Последствия

- В настоящем ядре `libplinth_ffi.so` под arm64 выросла на 0,49 МБ (2,21 →
  2,71 МБ). Это меньше, чем в пробе: стандартная библиотека уже внутри.
- Скан читает теги без картинок (`read_cover_art(false)`): чтение идёт до
  записи в базу, и сотни обложек в памяти скану ни к чему. Встроенную
  обложку ядро достаёт отдельным чтением файла, по запросу.
- Нужен ли Symphonia — вопрос v0.3: отпечатки можно считать и из PCM
  системного декодера. Если нужен, декодеры AAC, ALAC, FLAC, MP3, Vorbis и
  PCM вместе с разбором контейнеров добавят около 1,16 МБ на arm64.
  Вместе с `lofty` это +1,81 МБ против +1,16 МБ, если бы теги читала
  Symphonia. Разница — примерно 0,65 МБ на ABI — цена записи тегов и
  битрейта.
- Кодировку `lofty` берёт из тега. Кириллицу в CP1251 из ID3v1 и из
  «Latin-1» ID3v2 он не угадает. В коллекции автора таких файлов не нашлось,
  угадывание кодировки отложено до жалобы.
- MPL-2.0 у Symphonia совместима с AGPLv3 ([ADR 0003](0003-license-agplv3.md)),
  если в v0.3 она понадобится: её условия действуют пофайлово.
