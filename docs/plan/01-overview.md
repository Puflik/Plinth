# 1. Обзор проекта

## 1.1. Проблема

Ни один существующий аудиоплеер не закрывает сценарий целиком. Каждый силён в одном и провален в другом.

| Решение | Сильная сторона | Чем не устраивает |
|---|---|---|
| Яндекс Музыка | Хорошая инфа о треках и артистах, рекомендации | **Цензура треков**, региональные изъятия из каталога, подписка |
| Spotify | Рекомендации, UX | **Цензура**, уход лейблов, нет lossless в большинстве тарифов |
| Soundcore и подобные | Бесплатность | **Малый каталог** |
| Локальные плееры (Poweramp, Musicolet) | Оффлайн, качество, контроль | **Нет онлайна**, нет открытий, каталог мёртвый |
| Онлайн-плееры | Каталог | **Нет полноценного оффлайна** |
| **YouTube** | Лучшие рекомендации, **максимальный каталог**, нет цензуры | Нет работы с треками на устройстве, **не играет при выключенном экране** (обходится через Vanced/ReVanced) |

**Суть проблемы:** рынок делит плееры на «оффлайн» и «онлайн», а пользователь живёт в обоих режимах одновременно.

## 1.2. Идея продукта

> **Автономное Android-приложение, в котором трек — это логическая сущность, а не файл и не ссылка. У одного трека может быть несколько источников: локальный файл, поток с YouTube, покупка на Bandcamp, запись с Internet Archive. Приложение само выбирает лучший доступный источник в текущих условиях, а пользователь просто нажимает play и не думает, откуда идёт звук.**

Три фундаментальных следствия:

1. **Разделения «онлайн/оффлайн» не существует.** Оно было следствием того, что в других плеерах трек = источник.
2. **Каталог не может умереть.** Удалили видео, ушёл лейбл, заблокировали регион — трек остаётся в библиотеке со всей статистикой и ищет себе новый источник.
3. **Качество растёт со временем.** Нашёл трек в 160 kbps, потом купил FLAC — это тот же трек, просто теперь он звучит лучше. Прослушивания, лайки, места в плейлистах сохраняются.

## 1.3. Архитектурная модель C₁

Из четырёх рассмотренных вариантов (A — чистый агрегатор, B — своя библиотека + сервер, C — гибрид с плагинами, D — официальные API стримингов) выбран уточнённый гибрид **C₁**:

- **Нет центрального бэкенда.** «Сервер» — это само конечное устройство.
- **Плагинная система источников.** Локальные файлы, онлайн-провайдеры, внешние медиасерверы — всё через единый интерфейс.
- **Десктоп — равноправный узел**, а не сервер.
- **Синхронизация — опциональная надстройка** поверх журнала операций, транспорт подключаемый.

Вариант D отброшен как технический тупик: Spotify Web API не отдаёт аудиопоток (только управление их собственным SDK), требует Premium, и цензура с региональными ограничениями никуда не девается.

## 1.4. Цели и критерии успеха

| Цель | Критерий |
|---|---|
| Ежедневное использование автором | Автор перестал открывать YouTube ради музыки |
| Обучение | Освоены Rust, FFI, Android-медиастек, CRDT |
| Открытый проект | Репозиторий читаем, собираем сторонним человеком, есть документация |
| Снятие исходных болей | Нет цензуры, есть оффлайн, есть онлайн, есть рекомендации, играет при выключенном экране |

Обе цели автора — «хочу пользоваться каждый день» и «хочу научиться и разобраться» — приняты как равноправные. Это влияет на выбор стека (раздел 3.5) и на режим работы с AI (раздел 23.3).

## 1.5. Антицели — чего проект НЕ делает

- **Не обходит DRM.** Извлечение аудио из Spotify / Apple Music / Яндекса / Deezer не проектируется и не реализуется. См. раздел 22.
- **Не публикуется в Google Play.** Осознанный отказ ради свободы архитектуры.
- **Не становится сервисом.** Нет серверов автора, нет аккаунтов на стороне автора, нет сбора данных пользователей.
- **Не гонится за паритетом со Spotify по срокам.** Полный реестр фич — это годы.
- **Не делает мобильный клиент на Tauri.** Причины — в разделе 3.5.
- **Не поддерживает Android Auto и Wear OS** (фича 134 отклонена явно).

## 1.6. Идентичность проекта

| | |
|---|---|
| **Имя** | **Plinth** — постамент, основание, на котором что-то стоит |
| **Package ID** | `io.github.puflik.plinth` — домен не нужен, стандартная схема для F-Droid |
| **Имя ядра** | `plinthcore` |
| **Пасхалка** | Ник автора спрятан в самом имени: `p, l, i` из `puflik`. Дополнительно — в package ID и экране «О программе» |
| **Лицензия** | **AGPLv3** |

### Почему именно это имя

Рассматривались и отброшены: `APlayer` (рабочее, коллизия с известным HTML5-плеером DIYgod — проект не нашли бы поиском), `Fulcrum` (распадается на «full crime»), `Kuiper` (сильная метафора, но разнобой в русском произношении: Куйпер / Кайпер / Койпер), `Uplift` и `Uplink` (больше всего спрятанных букв, но высокие коллизии в поиске), `Flint`, `Pulsar`, `Kilter`, `Filament`, `Tessera`, `Amber`, `Timbre`.

Критерии выбора: реальное английское слово · однозначное произношение на обоих языках · ник спрятан, а не выставлен · низкие коллизии в поиске · пригодность для иконки в 48px.

### Почему AGPLv3, а не GPLv3

Цель автора сформулирована прямо: **«никто не должен суметь форкнуть и сделать закрытую экосистему типа Яндекс Музыки и выложить продаваться»**.

В GPLv3 для этого есть дыра — **SaaS loophole**:

| Сценарий | GPLv3 | AGPLv3 |
|---|---|---|
| Форкнули, добавили рекламу, **раздают APK** | ✅ Обязаны открыть исходники | ✅ Обязаны |
| Форкнули, подняли **серверный сервис** на этом коде, бинарники не раздают | ❌ **Ничего не обязаны** | ✅ Обязаны открыть |

GPL срабатывает только при распространении бинарников. Сетевой сервис формально ничего не распространяет. Для этого проекта дыра реальная: Rust-ядро с матчингом версий, движком рекомендаций и агрегацией провайдеров — ровно то, что удобно поднять серверным бэкендом.

**Важное уточнение:** AGPL не запрещает продавать. Продавать можно — но покупателю обязаны отдать полный исходник с правом раздавать дальше бесплатно. Первый же покупатель может выложить всё публично, совершенно легально. Бизнес-модель умирает в первый день. Именно поэтому AGPL запрещена внутренними политиками Google, Amazon и большинства крупных компаний — **и для этого проекта это плюс, а не минус**.

### Что рассматривалось и отброшено по лицензии

**Source-available лицензии с прямым запретом продажи** (PolyForm Noncommercial, Commons Clause, BSL) отброшены, потому что цена слишком высока:

| Потеря | Критичность |
|---|---|
| **F-Droid отказывает** — принимает только FOSS-лицензии | Основной канал после GitHub исчезает |
| **NewPipeExtractor использовать нельзя** — GPL запрещает добавлять ограничения к производной работе | **Жёсткий блокер**: путь к YouTube-провайдеру закрывается |
| Контрибьюторов почти не будет | Противоречит цели «хочу, чтобы пользовались» |
| «Некоммерческое» юридически размыто | Реклама — коммерция? Корпоративное внутреннее использование? Практики мало |
| Нельзя называть проект open source | Часть аудитории отвернётся |

Вывод: запрет продажи докупает почти ноль дополнительной защиты сверх AGPL, а стоит F-Droid и YouTube-провайдера.

### Что AGPLv3 означает для самого автора

| Ситуация | Можно ли закрыть код |
|---|---|
| Весь код написал автор один | ✅ Да — он правообладатель и может параллельно выпустить тот же код под любой другой лицензией (двойное лицензирование) |
| Уже выпущенные AGPL-версии | ❌ Остаются AGPL навсегда, форк с последнего открытого коммита законен |
| Принят pull request без CLA | ❌ Контрибьютор становится совладельцем своего куска |
| Взят код из GPL/AGPL-проекта (NewPipeExtractor) | ❌ Заперто окончательно |

Автор выбрал цель «чтобы **чужие** не смогли закрыть», а не «чтобы **я сам** не смог». Политика CLA поэтому остаётся свободным выбором и не является срочной.

## 1.7. Политика контрибьюций

Принято: **«внутренняя дисциплина сразу, публичные гарантии позже»**.

| С первого дня | Позже, только если появится реальный спрос |
|---|---|
| Провайдер — `trait` с чётким документированным контрактом | Заморозка контракта |
| `docs/ARCHITECTURE.md` и ADR ведутся с v0.1 | Версионирование и политика депрекации |
| `CONTRIBUTING.md`, PR принимаются: переводы, мелкие фиксы, темы, починка провайдеров | Гайд «напиши свой провайдер» |
| Код пишется так, будто его будут читать чужие | Тесты совместимости плагинов |

**Политика CLA: без CLA.** Contributor License Agreement дал бы автору право перелицензировать чужой вклад, в том числе закрыть код. Но цель сформулирована как «чтобы **чужие** не закрыли», а не «чтобы **я** мог». Отсутствие CLA делает проект необратимо открытым — что совпадает с целью — и не отпугивает контрибьюторов лишней бюрократией.

**Обоснование.** Внутренняя дисциплина одинакова в обоих вариантах. Разница только в *обещании стабильности*, и давать его до того, как форма контракта проверена четырьмя провайдерами, — вот что дорого.

**Дополнительный аргумент именно для этого проекта:** разработка идёт через AI-агентов, а рефакторинг — основной способ исправлять архитектуру, которую агент сгенерировал не так. Замороженный публичный API означает, что ранние ошибки проектирования нельзя будет исправить — они станут обязательствами перед чужими плагинами.

**Арифметика:** версионирование, политика совместимости, гайд и тесты совместимости — это 3–5 недель при 60 часах в месяц. До v1.0 их взять негде. Когда контракт вылизан практикой, заморозка стоит неделю вместо месяца.

**Проверка реальностью:** ни NewPipe, ни ViMusic, ни Metrolist, ни Musicolet не имеют публичного плагинного API. Все экстракторы лежат внутри репозитория. Их используют миллионы, им шлют PR, они на F-Droid. NewPipeExtractor выделился в отдельную библиотеку через годы, когда контракт уже устоялся.

### Ожидаемый поток чужих PR

| Тип | Частота | Полезность |
|---|---|---|
| Переводы на другие языки | Очень часто | Высокая, риск нулевой |
| Мелкие фиксы UI, опечатки | Часто | Высокая |
| Починка сломавшегося провайдера | Регулярно, после поломок YouTube | **Очень высокая** — чинят быстрее, чем автор один |
| Темы оформления | Иногда | Средняя |
| Глубокие правки в ядро | Редко | Требуют вдумчивого ревью |

### Требуемая документация

**Обязательна в любом случае**, независимо от политики API:

`README` со скриншотами и установкой · `CONTRIBUTING.md` · `docs/ARCHITECTURE.md` — обзор модулей и потоков данных · ADR — записи о принятых решениях и почему · F-Droid-метаданные · changelog · релизные заметки

⚠️ `ARCHITECTURE.md` и ADR нужны не только людям. При работе через AI-агента они требуются **каждую сессию**, чтобы агент не переизобретал уже принятые решения. Это рабочий инструмент, а не накладные расходы.
