# 2. Ключевые концепции

Это сердце проекта. Всё остальное — следствия.

## 2.1. Track / Version / Source — трёхуровневая модель

```
        Track                    «Radiohead — Creep»
        ↑ лайки, счётчики, история, места в плейлистах
        │
        ├── Version              «Original (explicit)»
        │     ├── Source         local:/Music/Creep.flac       lossless
        │     └── Source         youtube:abc123                Opus 160
        │
        ├── Version              «Clean»
        │     └── Source         provider:xyz                  AAC 256
        │
        └── Version              «Live at Glastonbury 2003»
              └── Source         archive.org:etree/...         FLAC
```

| Уровень | Что это | Что на нём живёт |
|---|---|---|
| **Track** | Логическая песня | Лайки, счётчик прослушиваний, дата добавления, позиции в плейлистах, профиль вкуса |
| **Version** | Конкретная запись | Метка explicit/clean, тип (студия / live / acoustic / remaster / radio edit), длительность, отпечаток |
| **Source** | Откуда взять байты | Провайдер, идентификатор, формат, битрейт, доступность, кэш-статус |

**Почему уровней три, а не два.** Два уровня (трек → источник) ломаются на цензуре: включаешь любимый трек, а играет версия с заглушенным словом. Три уровня разводят «песня», «какая именно запись» и «откуда поток».

**Критическое следствие:** статистика живёт на уровне **Track**. Слушал clean на работе, explicit дома — счётчик один, профиль вкуса один.

## 2.2. Политика версий — ответ на цензуру

Глобальная настройка, видимая даже в простом режиме:

```
Предпочитаемая версия:  (•) Оригинальная (explicit)   ← умолчание
                        ( ) Без мата (clean)
                        ( ) Любая доступная
```

**Поведение:**
- Единственный доступный источник отдаёт clean, а выбран explicit → приложение ищет explicit-версию у других провайдеров и предпочитает её.
- Нашлось только clean → играет clean, но показывает объяснение по тапу: «Оригинальная версия не найдена ни у одного провайдера» + кнопка «искать ещё».
- Обратный сценарий (нужна clean — машина с детьми, работа) — тот же переключатель, вся библиотека подменяется.

Такого нет ни в Spotify, ни в Яндексе, ни в YouTube Music — там версию за тебя выбирает лейбл и регион.

**Отдельно:** Яндекс и Spotify не только цензурируют, но и **выкидывают треки из каталога целиком** (региональные блокировки, уход лейблов, скандалы с артистами). Это не проблема версий — это проблема источника, и её решает сам факт многопровайдерности.

## 2.3. Слой открытий и слой любимого

Разрешение конфликта между «большой каталог без цензуры» и «hi-fi качество». Эти требования несовместимы для одного трека, но совместимы для библиотеки.

```
СЛОЙ ОТКРЫТИЙ                        СЛОЙ ЛЮБИМОГО
YouTube, SoundCloud                  Локальные файлы, Bandcamp-покупки,
Opus 160 / AAC 256                   Internet Archive, свой сервер
максимальный каталог                 lossless
                    │                         ▲
                    └─────────────────────────┘
                       трек постепенно «оседает»
```

### Лестница качества

```
Bandcamp (купленный)  ──┐
Локальный FLAC/ALAC   ──┼──► Lossless
Свой Navidrome        ──┤
Internet Archive      ──┘
─────────────────────────────────────
Локальный MP3 320     ──┐
YT Music Premium 256  ──┼──► High lossy
─────────────────────────────────────
YouTube Opus ~160     ──┐
SoundCloud 128        ──┼──► Standard
Bandcamp стрим 128    ──┘
```

### Объективное ограничение рынка

**Бесплатного легального lossless с большим каталогом популярной музыки не существует.** Это состояние индустрии, а не пробел архитектуры. Lossless реально достижим через: покупки (Bandcamp, Qobuz Store, 7digital, HDtracks), Internet Archive, рипы своих CD, собственные файлы.

## 2.4. Апгрейд трека

Механизм, реализующий 2.3. Фоновая задача периодически проверяет: не появился ли у трека источник лучшего качества?

**Что приложение делает само:**
- Находит трек у всех подключённых провайдеров и выбирает лучшее доступное качество
- Скачивает в кэш/загрузки в фоне по политике
- Периодически перепроверяет наличие лучшего источника → нашёлся → скачивает и заменяет, статистика сохраняется
- Скачивает FLAC с Bandcamp, если альбом **куплен** и аккаунт привязан
- Подхватывает файл, положенный пользователем в папку, и привязывает его по акустическому отпечатку к существующему Track

**Чего приложение не может:** создать lossless там, где его нет в бесплатном доступе.

**Промежуточный сценарий:** ненавязчивая плашка «Этот альбом ты слушал 47 раз. На Bandcamp он есть в FLAC за $7». Один осознанный клик в браузер, дальше всё автоматом навсегда.

## 2.5. Деградация источников

| Событие | Поведение |
|---|---|
| Источник недоступен, есть другие | Молча переключиться, пользователь ничего не заметил |
| Источников не осталось | **Не удалять трек.** Пометить «недоступен», сохранить место в плейлистах и всю статистику |
| Периодически | Фоновая задача ищет замену: «трек снова доступен у другого провайдера» |

Spotify в такой ситуации делает трек серым навсегда. Здесь — нет.

## 2.6. Простой и продвинутый режимы

Переключатель в настройках между «приложение решает всё» и «я решаю всё».

**Важно архитектурно:** это **пресет интерфейса**, а не выбор архитектуры. Под капотом всегда реализован промежуточный вариант — движок автоматических решений **плюс** точка переопределения у каждого решения. «Простой режим» их прячет, «продвинутый» показывает.

Причина: из чистой автоматики нельзя дёшево получить контроль (нет точек переопределения), из чистого контроля нельзя дёшево получить автоматику (нет движка решений). Промежуточный вариант содержит оба, и скрыть контрол дешевле, чем добавить.

**Третий, сквозной уровень — объяснимость.** Каждое автоматическое решение раскрывается по тапу в обоих режимах:

> ♪ Играет: Creep (Clean)
> ⓘ *Оригинальная версия не найдена. Источник: YouTube, Opus 160 — лучший доступный.*
> [искать ещё] [не показывать clean никогда]

## 2.7. Список розыска (фича 142)

**Сценарий:** человек ищет трек, а его нет **ни в локальных файлах, ни у одного провайдера**. Причины реальные: очень редкий релиз или демо-запись · локальная группа без дистрибуции · трек удалён отовсюду по требованию правообладателя · региональная блокировка сразу везде.

**Вся машинерия для этого уже есть.** Концепция 2.5 умеет держать `Track` без доступного `Source` и фоново искать замену. «Разыскиваемый трек» — то же самое состояние, просто попавшее туда с другой стороны.

```
Поиск ничего не нашёл
   → кнопка «искать дальше»
   → создаётся Track без источников, статус «разыскивается»
   → фоновая задача периодически опрашивает провайдеров
   → появился → уведомление
```

> *«Нашёлся трек, который ты искал полгода назад»*

Новой машинерии — ноль. Волна v0.9, вместе с фоновыми задачами. Разыскиваемые треки можно добавлять в плейлисты — они там просто серые до момента, пока не найдутся.
