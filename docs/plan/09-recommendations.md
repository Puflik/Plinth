# 9. Рекомендации и открытия

Главный дифференциатор проекта: «хорошие рекомендации как у YouTube, но без их сервера».

## 9.1. Общая схема

```
СБОР СИГНАЛОВ (локально, всегда)
   прослушал целиком ++      скип до 30% −−       повтор подряд +++
   лайк ++                   добавил в плейлист +  удалил из библиотеки −
   контекст: время суток, день недели, наушники/колонка, что играло до
                              │
                              ▼
ПРОФИЛЬ ВКУСА (локально, SQLite)
   веса по артистам · жанрам и тегам · эпохам · аудио-характеристикам
   отдельные срезы: «утро», «вечер», «за работой», «выходные»
                              │
                              ▼
ГЕНЕРАЦИЯ КАНДИДАТОВ
   ListenBrainz similar  ·  MusicBrainz граф  ·  Last.fm similar
   провайдерское радио   ·  своя библиотека (забытое)
   локальный аудио-анализ (похоже по звучанию — работает офлайн)
                              │
                              ▼
РАНЖИРОВАНИЕ (локально)
   скор = совпадение с профилем × новизна × контекст
          − штраф за недавнее − чёрный список
   ползунок «знакомое ↔ новое» двигает вес новизны
```

## 9.2. Три движка открытий

| Движок | Источник данных | Что умеет | Офлайн |
|---|---|---|---|
| **ListenBrainz / MusicBrainz** | Открытая база прослушиваний + граф артистов | «Похожие артисты», «похожие треки», коллаборативная фильтрация по данным миллионов людей | Нет |
| **Провайдерский** | YouTube Music radio, SoundCloud related, Bandcamp «fans also like» | Готовые качественные миксы и радио | Нет |
| **Локальный ранжировщик** | Своя история: скипы, повторы, время суток, последовательности + локальный аудио-анализ | Умная перемешка, «то, что слушаешь по утрам», забытые треки, «похоже по звучанию» | **Да** |

**Ключевой момент:** ListenBrainz — open-source проект MetaBrainz с открытым API и свободными данными. Он даёт коллаборативные рекомендации **без собственного сервера и без цензуры**. Обычно рекомендации требуют, чтобы кто-то собирал данные всех пользователей — здесь этот кто-то уже существует и данные отдаёт даром.

**Решение по 10c: используются все три уровня**, с приоритетом «локально → открытые базы → провайдер».

## 9.3. Холодный старт — 11 источников стартового профиля

Самая большая проблема рекомендаций: поставил приложение, библиотека пустая, истории нет, рекомендовать не из чего.

| № | Источник | Что даёт | Цена |
|---|---|---|---|
| 1 | **Импорт из Spotify** (официальный API) | Плейлисты, лайки, топ-артисты, топ-треки | OAuth-обвязка |
| 2 | **Импорт из Яндекс Музыки** | То же | OAuth-обвязка |
| 3 | **Импорт из Last.fm** | **Полная история прослушиваний**, иногда за 10+ лет | Просто, публичный API |
| 4 | **Импорт из ListenBrainz** | То же, открытый формат | Просто |
| 5 | **Анализ локальной библиотеки** | То, что уже лежит на устройстве, — это уже вкус | Бесплатно, работает сразу |
| 6 | **Опрос при первом запуске** («отметь 5 артистов») | Работает для совсем новых | Дёшево, но грубо |
| 7 | **Импорт из YouTube / YouTube Music** | Лайки и плейлисты через Google Takeout или API | Средне |
| 8 | **Импорт плейлиста по ссылке** (через Odesli) | Любой сервис — одна ссылка → профиль | Дёшево |
| 9 | **Импорт бэкапов других плееров** (Poweramp, Musicolet, VLC) | История и плейлисты локальных плееров | Разбор форматов |
| 10 | **Импорт из Apple Music / Deezer / VK** | Плейлисты и лайки | По наличию API |
| 11 | **Обмен профилем вкуса между устройствами/людьми** по тому же P2P-каналу, что и синк | «Дай послушать, что ты слушаешь». Нового такого нет нигде | Бесплатно — транспорт уже есть |

**Решение по 10a:** берутся все, в порядке приоритета реализации 5 → 3 → 1 → 6 → остальные.

**Замечание по №11:** это побочный продукт архитектуры. Раз уже есть P2P-транспорт и CRDT-журнал, обмен профилями вкуса между людьми почти ничего не стоит — а это фича, которой нет ни в одном стриминге, потому что там профиль вкуса принадлежит сервису, а не тебе.

## 9.4. Собираемые сигналы

**Собираем:** `прослушал целиком` · `скип и на какой секунде` · `повтор` · `лайк` · `добавление в плейлист` · `удаление` · `время суток` · `день недели` · `тип вывода (наушники / колонка / внешний ЦАП)` · `предыдущий трек в сессии` · `громкость`

**Не собираем:** ❌ `поисковые запросы` — пользы для профиля вкуса мало, ощущение слежки максимальное.

Время суток и тип вывода дают наибольший прирост качества рекомендаций (утренний микс, «в наушниках слушаю другое»), а данные не покидают устройство. Поэтому они включены, но под общим переключателем в разделе приватности:

> **Расширенные сигналы** — учитывать время суток, день недели и тип подключённого устройства. `Включено`
> *Данные не покидают устройство.*

## 9.5. Приватность рекомендаций

- Профиль вкуса хранится **только локально**, не покидает устройство (кроме явной синхронизации между своими устройствами и явного обмена по п. 11)
- Во внешние базы уходит минимум: «я слушал вот это» → приходят «похожие»
- Скробблинг выключен по умолчанию, пока не привязан аккаунт
- Провайдерское радио означает, что провайдер видит запрос — это отражено в объяснении решения

## 9.6. Объяснимость

Каждая рекомендация раскрывается: «потому что ты слушал X», «похоже по звучанию на Y», «ты слушал это по утрам», «из радио YouTube». Фича 106.
