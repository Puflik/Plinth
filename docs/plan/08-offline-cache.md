# 8. Оффлайн: кэш и загрузки

## 8.1. Два разных понятия

Принципиальное разделение, без которого система ломается:

| | **Кэш** | **Загрузки** |
|---|---|---|
| Кто создаёт | Приложение само (пользователь не думает) | Пользователь явно нажал «скачать» |
| Лимит | Адаптивный, см. 8.2 | **Без лимита** |
| Вытеснение | Автоматическое, тихое | **Никогда** |
| Удаление | Само | Только вручную |
| Раздел в UI | «Хранилище» | «Загрузки» |

**Сценарий, который это защищает:** скачал перед самолётом альбом в FLAC → неделю слушал всякое онлайн → кэш переполнился → автовытеснение снесло альбом → в самолёте тишина. С разделением это невозможно.

## 8.2. Адаптивный лимит кэша

Лимит измеряется **в треках**, а не в мегабайтах — пользователь думает треками.

```
Лимит кэша = min(
    N треков            ← 250 по умолчанию, ручка в продвинутом режиме
    X% свободного места ← 20% по умолчанию, предохранитель
)
```

Почему нужен предохранитель:

| Качество | 250 треков весят |
|---|---|
| Opus 160 | ~1 ГБ |
| MP3 320 | ~2 ГБ |
| FLAC | **~6 ГБ** |

Без второго ограничителя приложение на забитом телефоне молча съест 6 ГБ.

**В UI — живой пересчёт по фактическому среднему весу:**

> **Кэш:** `250 треков` · сейчас занято 1,4 ГБ из ~2,1 ГБ

## 8.3. Вытеснение

Применяется **только к кэшу**, не к загрузкам.

Порядок вытеснения: давно не слушанное → редко слушанное → большое по размеру.
**Никогда не вытесняется:** лайкнутое, в активных плейлистах, скачанное явно.

## 8.4. Политика качества

| Условие | Поведение |
|---|---|
| Wi-Fi | По пресету качества (умолчание — «Баланс») |
| Мобильная сеть | По отдельному пресету, по умолчанию экономнее |
| Нет сети | Локальный файл или кэш |
| Скачивание | Только по Wi-Fi (умолчание) |
| Место хранения | Память устройства или SD — спросить один раз при первом запуске |
