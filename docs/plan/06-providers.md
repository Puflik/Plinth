# 6. Провайдеры контента

## 6.1. Интерфейс провайдера

Единая абстракция, которую реализует каждый источник:

```
Provider:
    search(query, filters) → [SearchResult]
    resolve(external_id) → VersionInfo + [SourceOption]
    stream_url(source, quality) → URL + headers
    download(source, quality) → bytes
    browse(section) → [Item]            // чарты, новинки, коллекция
    related(external_id) → [SearchResult]  // провайдерское радио
    capabilities() → {качества, форматы, умеет ли related, ...}
    health() → OK / Degraded / Down
```

**Принцип проектирования:** всё изменчивое (эндпоинты, паттерны, параметры, сигнатуры) живёт **в данных, а не в коде**. Это делает переход на удалённое обновление конфигов (раздел 6.3) полудневной работой вместо переписывания.

## 6.2. Каталог провайдеров и порядок реализации

| Провайдер | Каталог | Сложность | Стабильность | Легальность |
|---|---|---|---|---|
| **Internet Archive** | Нишевый: концерты, public domain. Зато **FLAC** | Очень низкая, открытый API | Годами не меняется | Чисто |
| **Bandcamp** | Большой: инди, электроника, метал | Низкая | Стабилен | Чисто |
| **SoundCloud** | Большой, много эксклюзива | Средняя | Ломается изредка | Серая зона |
| **YouTube** | **Максимальный** | **Очень высокая**: PoToken, сигнатуры, throttling, капчи | **Ломается раз в 1–3 месяца** | Серая зона |
| Subsonic / Navidrome / Jellyfin | Свой домашний сервер | Низкая, документированный протокол | Не меняется годами | Чисто |

### Порядок реализации

```
v0.2  Internet Archive  ← ПЕРВЫЙ. Простейший API, обкатка интерфейса провайдера
                          Минимальный объём: только поиск + стрим
v0.5  Bandcamp          ← второй, вместе с кэшем, загрузками и политиками качества
v0.9  SoundCloud        ← первый «серый», проверка устойчивости абстракции
v1.0  YouTube           ← максимальный каталог, максимальная поддержка
v2+   Subsonic          ← дальний бэклог, дешёвый бонус для аудитории
```

**Обоснование порядка.** YouTube настолько сложен и нестабилен, что на нём невозможно понять, где кончается своя абстракция и начинается их защита. Отладив интерфейс на простом провайдере, потом воткнёшь YouTube в готовую форму. Наоборот — абстракция срастётся с особенностями YouTube, и второй провайдер потребует переписывания.

**Почему Internet Archive переехал из v0.7 в v0.2.** Первоначально интерфейс провайдера планировался в v0.5. Перенос даёт три выигрыша:

1. **Абстракция провайдера проверяется на самом простом возможном случае** — открытый документированный API, никакой защиты от парсинга
2. **Приложение никогда не бывает пустым** начиная с v0.2. Это снимает худший сценарий первого запуска: «поставил, а слушать нечего», актуальный для тех, у кого нет локальных файлов
3. **Модель Track/Version/Source сразу работает с онлайн-источником**, а не достраивается под него через три волны

**Чтобы не раздувать v0.2, объём провайдера строго минимальный:** поиск + стрим. Без кэша, без загрузок, без политик качества, без апгрейда — всё это приходит в v0.5 вместе с Bandcamp. Цена переноса: **+30–40 часов** к волне.

⚠️ **Осознанный компромисс:** до v1.0 приложение **не заменяет YouTube** — каталог будет инди, концерты и public domain. Полноценным оно станет примерно через 10–16 месяцев.

### Что отброшено

- **Spotify / Apple Music / Яндекс / Deezer как источник звука** — DRM, см. раздел 22
- **Qobuz / Tidal подписка** — то же самое. Но **Qobuz Download Store** (покупки) — легитимный источник lossless

## 6.3. Обновление экстракторов (фича 67)

Фазированная стратегия — снимает необходимость выбирать:

| Этап | Механизм | Скорость реакции | Обоснование |
|---|---|---|---|
| **v0.5–v0.9** | Обновление приложения | Дни–недели | Bandcamp и Archive не ломаются. Удалённый конфиг был бы инфраструктурой без задачи |
| **v1.0 (YouTube)** | **+ Удалённый конфиг** — приложение тянет с GitHub файл с правилами (паттерны, эндпоинты, параметры). Кода не качает, только данные | **Часы** | Появляется провайдер, ломающийся раз в 1–3 месяца |

**Отброшен третий вариант — скачиваемые плагины как исполняемый код.** Даёт ту же скорость, но открывает дыру в безопасности и прямо запрещён политиками сторов (хотя Google Play и так исключён, риск для пользователей остаётся).

## 6.4. Фоллбэк и деградация

- Провайдер вернул ошибку → пометить `Degraded`, попробовать следующий по порядку
- Провайдер недоступен N раз подряд → `Down`, исключить из поиска на время, показать в настройках
- Порядок провайдеров: по умолчанию — по качеству и скорости ответа; настраивается в продвинутом режиме (решение №1)
- Обход региональных блокировок (фича 65) — через настраиваемый прокси
