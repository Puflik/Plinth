# 15. Тестирование, CI и качество

Раздел важнее обычного: разработка идёт **соло через AI-агентов**. Без тестов регрессии проникают незаметно — агент не помнит, что ломает, а автор не может удержать в голове весь проект.

## 15.1. Стратегия тестирования

Принят вариант **«ядро покрываем серьёзно, Android — только smoke»**. Цена: +25–35 % времени к каждой волне.

| Слой | Покрытие | Тип |
|---|---|---|
| **Rust-ядро** `matching`, `policy`, `cache`, `recommender`, `sync` | **Цель 70 %+** | Unit-тесты, обязательны |
| **Провайдеры** | Ключевые сценарии | Интеграционные на **записанных HTTP-фикстурах** — CI не ходит в сеть и не ломается от чужих изменений |
| **Android UI** | Минимум | Smoke-тест воспроизведения обязателен, остальное по остаточному принципу |
| **Алгоритм склейки** | Отдельный корпус | Набор реальных пар «одно и то же / разное» как регрессионный эталон |

**Когда пишутся тесты:** для ядра — **вместе с кодом** (там легко ошибиться незаметно: политика выбора источника, ранжирование, вытеснение кэша). Для остального — после.

## 15.2. Ревью кода, написанного AI

Три правила:

1. **«Не мержу то, чего не понимаю.»** Если не можешь объяснить, как работает — не мержится
2. **Тест принимается только после мутационной проверки.** Тесты пишет агент (с 2026-10-01; раньше правило было «пишет автор»), и проверяет он тогда своё же понимание задачи — поэтому каждый новый тест обязан падать, когда исправление или проверяемая строка возвращена к ошибке. Тест, который остаётся зелёным без исправления, не принят
3. **Ревью в чистом контекстном окне.** Отдельный чат, который не видел, как код писался, получает только диф и нужный раздел ТЗ

```
Готов кусок → НОВЫЙ чат (чистый контекст)
   вход:  plan.md (релевантный раздел) + диф + тесты
   задача: «найди, что сломается»
   выход: список замечаний
→ правки → мерж
```

**Обоснование третьего правила:** агент-автор склонен защищать своё решение и воспроизводить те же допущения, из-за которых ошибся. Агент без контекста видит код как чужой и проверяет его против требования, а не против собственного замысла.

**Частота:** раз в волну сплошным проходом по всему, что в ней вошло, **до релиза волны** (v0.1 — `docs/review/v0.1-review.md`; v0.2 — задача Р1 в `tasks.md`). Изменение от 2026-10-01: прежде было «каждый PR в ядро» (`matching`, `policy`, `recommender`, `cache`, `sync`), но работа идёт ворктри → `main` без PR. Для этих пяти модулей, когда они появятся, ревью — ещё и до слияния ветки, а не только перед релизом.

## 15.3. CI/CD

| Этап | Содержание |
|---|---|
| Платформа | GitHub Actions |
| Проверки | `cargo test` · `cargo clippy` · `detekt` / `ktlint` |
| Сборка | APK под 4 ABI (arm64-v8a, armeabi-v7a, x86_64, x86) |
| Релиз | Тег → автосборка подписанного APK → GitHub Release |
| Версионирование | Семантическое |
| Сеть в CI | **Запрещена** — провайдеры тестируются на фикстурах |
