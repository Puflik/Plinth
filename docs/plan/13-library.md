# 13. Библиотека, теги, плейлисты, импорт

## 13.1. Сканирование

| Параметр | Решение |
|---|---|
| Папки | Настраиваемые, умолчание `Music` + `Download`. Исключения поддерживаются |
| Режим | **Инкрементальный по `mtime`**, не полный пересчёт каждый раз |
| Исполнение | Фоном через `WorkManager`, UI не блокируется |
| Триггеры | Запуск приложения · изменение в отслеживаемых папках · ручное «пересканировать» |
| Целевая скорость | 5 000 треков < 30 с · 50 000 треков < 5 мин |

## 13.2. Организация библиотеки

| Аспект | Решение |
|---|---|
| Album artist | Отдельное поле, приоритетнее `artist` при группировке альбомов |
| Множественные артисты | Разделители `;` `/` `feat.` `&` `x` — **список настраиваемый**, потому что у всех коллекций свои конвенции |
| Сборники | По `album artist` + флагу `compilation`. Не рассыпаются на 20 альбомов по одному треку |
| Многодисковые альбомы | Номер диска учитывается, треки не перемешиваются |
| Режим «Папки» | Отдельный вид просмотра — файловая структура как есть (фича 29) |
| Сортировка | **Естественная** — `Track 2` перед `Track 10`, а не после |
| Артикли | **Игнорируются при сортировке** (`The Beatles` → под «B»). Настройка обязательна, со списком артиклей по языкам: `The`, `A`, `An`, `Der`, `Die`, `Das`, `Le`, `La`, `Los` |
| Корзина | Удалённое хранится 30 дней, восстанавливается |

## 13.3. Теги — модель «C+: оверлей, экспорт и откат»

Рассматривались: только БД (файлы не трогаются, но другие плееры правок не увидят), запись прямо в файлы (необратимо, риск испортить коллекцию при баге), оверлей с экспортом.

**Принято — оверлей с экспортом и гарантированным откатом:**

| Слой | Поведение |
|---|---|
| **Правка** | Всегда пишется в БД как оверлей. Файл не трогается |
| **Экспорт в файлы** | Явное действие пользователя. Перед записью **оригинальные теги файла сохраняются в БД** |
| **Откат** | «Вернуть как было» работает всегда, даже через год — оригинал лежит в базе |
| **Запись** | Атомарная: временный файл → `rename`. Сбой посреди записи не бьёт коллекцию |
| **Внешние изменения** | Файл изменили другим плеером → замечаем по `mtime` → спрашиваем, чьи теги главнее |
| **Граница автоматики** | Подтянутое из MusicBrainz **никогда** не пишется в файлы само — только по явному «применить» |

⚠️ **Техническая заноза:** на Android 11+ запись в чужие файлы требует Storage Access Framework или `MediaStore`. Пользователю придётся выдать доступ к папке отдельно. Заложено в мастер онбординга как пропускаемый шаг «разрешить изменение файлов».

## 13.4. Плейлисты

**Обычные:** ручные, с папками (фича 51), drag & drop, импорт/экспорт M3U и PLS.

**Умные — гибридный ввод правил (принято):**

| Режим | Интерфейс |
|---|---|
| Простой | Визуальный конструктор условий, как в iTunes |
| Продвинутый | Текстовый синтаксис: `genre:rock AND year>2010 AND plays>5 SORT added DESC LIMIT 100` |

Оба режима работают над одной моделью правил — конструктор просто рендерит то же дерево условий.

**Доступные поля:** артист · album artist · альбом · жанр · год · рейтинг · счётчик прослушиваний · дата добавления · дата последнего прослушивания · длительность · битрейт · формат · **есть оффлайн** · **источник** · **версия (explicit/clean)** · теги · **артист в чёрном списке** · **трек недоступен**

Последние пять полей уникальны для этого проекта — их нет ни в одном существующем плеере, потому что там нет модели Track/Version/Source.

**Операторы:** `=` `≠` `>` `<` `содержит` `начинается с` `в списке` · группировка через `AND` / `OR` / скобки · сортировка · лимит.
