# 10. Синхронизация устройств

## 10.1. Принцип

Состояние — **журнал операций (CRDT)**, а не снимок БД. Синхронизация безразлична к транспорту.

## 10.2. Транспорты

| Способ | Суть | Статус |
|---|---|---|
| **LAN-прямое** | Телефон и ПК в одной Wi-Fi сети находят друг друга (mDNS) и синкаются напрямую | **Выбран**, v1.5 |
| **P2P / relay** | Syncthing-подобный подход, обход NAT | **Выбран**, v1.5 |
| Чужое «тупое» хранилище (Google Drive, WebDAV, Nextcloud) | Файл состояния лежит у пользователя | Отклонён |
| Опциональный self-host | Кто хочет — поднимает контейнер | Отклонён |

⚠️ **Нюанс, который надо знать:** чистый P2P через NAT требует **STUN**-сервер для «знакомства» узлов. Публичные бесплатные есть. Но примерно в 10% сетей (Symmetric NAT, мобильный CGNAT) без **TURN**-релея соединение не встанет, а TURN — это уже сервер. Не блокер, но «P2P» ≠ «совсем без инфраструктуры».

**Митигация:** LAN-прямое покрывает основной сценарий (телефон и ПК дома). P2P — для остальных случаев, с честным сообщением при невозможности соединения.

## 10.3. Что синхронизируется

| Синхронизируется | Не синхронизируется |
|---|---|
| Плейлисты | Аудиофайлы (только по явному запросу) |
| Лайки и оценки | Кэш |
| История прослушиваний | Локальные пути |
| Решения о склейке версий | Настройки, специфичные для устройства |
| Чёрный список рекомендаций | |
| Профиль вкуса | |
| Позиция воспроизведения («продолжить на другом устройстве») | |

## 10.4. Конфликты

CRDT разрешает автоматически. Неразрешимое (одновременное переименование плейлиста, например) — спросить один раз, решение запомнить.
