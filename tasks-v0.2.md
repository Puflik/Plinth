# Plinth v0.2 «Ядро и первый источник» — файловая декомпозиция

> **Родительский документ:** [tasks.md](tasks.md) · **Требования:** [plan.md](plan.md) · **Предыдущая волна:** [tasks-v0.1.md](tasks-v0.1.md)
> **Объём волны:** 92–140 ч · **Файлов:** ~130 (из них ~95 новых на Rust)
> **Что происходит:** данные переезжают из Room в Rust-ядро, появляется CRDT-журнал и первый онлайн-провайдер.

---

## Почему эта волна самая рискованная

v0.1 был обычным Android-приложением. v0.2 добавляет **четыре незнакомые технологии сразу**: Rust, FFI через UniFFI, CRDT и кросс-компиляцию под NDK. Ни одна из них не знакома автору.

Отсюда три следствия, определяющие порядок работы:

1. **Сначала пустое сквозное соединение.** Прежде чем писать модель данных, надо получить работающую цепочку «Kotlin вызвал Rust-функцию, которая вернула строку» на реальном устройстве. Пока эта цепочка не работает, всё остальное писать не во что.
2. **Замена Room на ядро — big-bang.** Половинчатого состояния не бывает: либо библиотека в Room, либо в ядре. Значит, ядро должно быть готово **полностью** до начала эпика D.
3. **CRDT выбирается прототипом, а не чтением документации.** Эпик C начинается с двух выброшенных прототипов — это заложено в оценку.

**Обозначения:** 📌 критический путь · 🔬 требует исследования · ⚠️ риск · 🆕 новый крейт

| `app/src/main/kotlin/.../core/CoreLogBridge.kt` | A3.4 | Приём логов из Rust |
| `app/src/main/kotlin/.../core/CoreErrorMapper.kt` | A3.3 | `CoreError` → `AppError` из v0.1 |
| `docs/adr/0010-ffi-boundary.md` | A3 | Что пересекает границу, что нет, и почему |

> 📌 ⚠️ **`panic.rs` — не формальность.** Без `catch_unwind` любой `unwrap` на кривых данных провайдера кладёт всё приложение, а в Play-консоли... которой у тебя нет. Пользователь увидит мгновенное закрытие без объяснений, а в логе будет невнятный `SIGABRT` без стектрейса Rust.
>
> **Правило: ни одна функция, видимая из Kotlin, не может паниковать.**

> **DoD эпика A:** Kotlin вызывает функцию ядра на реальном устройстве всех четырёх архитектур, получает результат, видит лог из Rust, а `panic` внутри ядра приходит как обычное исключение Kotlin.

# Порядок работы

```
1.  A1              Workspace и типы
2.  A2              📌 Сборка под Android — ДО написания логики
3.  A3 (минимум)    📌 Пустое сквозное соединение: Kotlin → Rust → строка обратно
    ─────────────── здесь проверяется, что вся связка вообще работает ───────────────
4.  C1              🔬 Прототипы CRDT и выбор библиотеки
5.  B1              Модель Track / Version / Source
6.  B2 → B3         SQLite, репозитории, миграции
7.  C2 → C3         Журнал и проекция
8.  A3 (полностью)  Настоящее API ядра поверх готовой модели
9.  D1 → D2         Сканер и теги на Rust
10. D3              🔁 Big-bang: удаление Room
11. D4              Пользовательские данные через журнал
12. C4              Зеркало журнала и восстановление
13. E1              📌 trait Provider
14. E2              Internet Archive
15. E3              Единый поиск и стрим в UI
16. F               Приёмка
```

**Почему шаг 3 раньше всего остального.** Кросс-компиляция Rust под четыре ABI, линковка NDK и генерация UniFFI-биндингов — это то, где новичок теряет дни на непонятные ошибки сборки. Выяснять это, имея за спиной готовую модель данных, которую некуда подключить, — худший сценарий. Сначала «hello from Rust» на реальном телефоне, потом всё остальное.

**Почему C1 раньше B1.** Выбор CRDT-библиотеки влияет на то, как выражаются операции, а операции — на форму модели. Обратный порядок означает переделку модели под выбранную библиотеку.

**Почему D3 так поздно.** Удаление Room — точка невозврата: после неё приложение не соберётся, пока ядро не заработает полностью. Делать это, пока модель или журнал не готовы, — значит остаться с несобирающимся проектом на неделю.

# Риски волны

| Риск | Вероятность | Митигация |
|---|---|---|
| **Сборка под NDK съест дни** | Высокая | Шаг 3 раньше всего. Если через 8 часов «hello from Rust» не заработал — остановиться и разобраться, а не обходить |
| **Размер APK выбьется за 30 МБ** | Средняя | Замер на первой сборке, профиль `opt-level="z"` + LTO + strip, при необходимости ABI splits |
| **Отладка через FFI мучительна** | Высокая | `panic.rs` + проброс логов Rust в Android-логгер делаются сразу, а не когда припечёт |
| **Journal распухнет** | Средняя | Критерий отбора библиотеки в C1.2 — размер на 10 000 событий. При проблеме — компакция журнала |
| **Big-bang в D3 затянется** | Средняя | Качество границы `LibraryRepository` из v0.1 определяет цену. Если граница течёт — чинить до начала D3 |
| **Соблазн сделать кэш в v0.2** | Высокая | Явная граница волны: только поиск и стрим. Кэш — v0.5 |
| **Rust окажется тяжелее ожиданий** | Средняя | Эта волна и есть проверка гипотезы. Если через 40 часов ядро не движется — честно пересмотреть R2, оставив v0.1 на Kotlin и отложив Rust до десктопа |
