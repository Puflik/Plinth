# Plinth v0.3 «Идентичность» — файловая декомпозиция

> **Родительский документ:** [tasks.md](tasks.md) · **Требования:** [plan.md](plan.md) · **Предыдущая волна:** [tasks-v0.2.md](tasks-v0.2.md)
> **Объём волны:** 50–80 ч · **Файлов:** ~75 (из них ~55 новых на Rust)
> **Что происходит:** приложение начинает понимать, что два разных файла — один и тот же трек, и что у трека бывают версии.

---

## Зачем эта волна

После v0.2 модель `Track / Version / Source` существует, но **не наполняется**: каждый найденный файл и каждый результат из Internet Archive создают отдельный `Track`. Библиотека выглядит как свалка дубликатов.

v0.3 включает механизм, ради которого вся эта модель затевалась:

```
до v0.3                          после v0.3
─────────────                    ──────────────────────────
Creep.flac              ──►      Track «Radiohead — Creep»
Creep (Remastered)      ──►        ├── Version «Original (explicit)»
creep [official video]  ──►        │     ├── Source local FLAC
Creep (Clean)           ──►        │     └── Source Internet Archive
                                   ├── Version «Clean»
4 записи в свалке                  └── Version «Remaster 2016»
                                 
                                 1 трек, 3 версии, статистика общая
```

И здесь же появляется **политика версий** — прямой ответ на исходную боль: «не хочу, чтобы за меня решали, слушать мне цензуру или оригинал».

**Обозначения:** 📌 критический путь · 🔬 исследование · ⚠️ риск · 🆕 новый крейт · 🔒 необратимость данных

>
> Ошибочно слитые треки без возможности отката — это тихая, необратимая порча библиотеки пользователя. Человек заметит через месяц, когда у «Creep» окажется 340 прослушиваний вместо 120, а живой концерт исчезнет из плейлиста.

# Порядок работы

```
1.  A1              🔬 📌 Проверка rusty-chromaprint — ДО всего остального
    ─────────────── точка принятия решения: Rust или откат на C ───────────────
2.  B1              Нормализация строк
3.  A2 (candidate)  📌 Отбор кандидатов — использует B1
4.  A2 (остальное)  Расчёт и хранение отпечатков
5.  B2              Каскад разрешения идентичности
6.  B4              🔒 Обратимость — ДО первой автоматической склейки
7.  B3              Порог и очередь спорных
8.  A3              AcoustID
9.  B5              Регрессионный корпус
10. C1              Определение explicit/clean
11. C2 → C3         Политика версий
12. D1 → D2 → D3    UI
13. E               Приёмка
```

**Почему A1 первым.** Вся волна стоит на предположении, что Rust-порт Chromaprint даёт корректные отпечатки. Если нет — меняется стек эпика A, и узнать это надо до того, как на отпечатках построены каскад, очередь и политика.

**Почему B1 раньше A2.** Отбор кандидатов (`candidate.rs`) опирается на нормализованные строки: дешёвая эвристика отсеивает 95 % работы для дорогого DSP. Без B1 придётся считать отпечатки всем подряд.

**Почему B4 раньше B3.** 🔒 Обратимость должна существовать **до того, как приложение склеит первую пару автоматически**. Обратный порядок означает окно, в котором пользовательские библиотеки портятся необратимо. Даже на своей собственной коллекции этого делать не стоит.

# Риски волны

| Риск | Вероятность | Митигация |
|---|---|---|
| **Отпечатки Rust-порта расходятся с эталоном** | Низкая (проверено в `plan.md` 5.2) | A1 первым шагом. Запасной путь — C через NDK, +8–12 ч |
| 🔒 **Ошибочные склейки портят библиотеку** | **Высокая при небрежности** | B4 до B3. Высокий порог автоматики. Тест обратимости — условие выпуска |
| **Расчёт отпечатков съедает батарею** | Средняя | `candidate.rs`: отпечаток только подозрительным парам, не всем подряд |
| **Матчинг слишком строгий** — дубликаты не склеиваются | Средняя | Корпус `same.json`. Порог настраивается в продвинутом режиме |
| **Матчинг слишком мягкий** — склеивает разное | Средняя | Корпус `different.json`. Спорное идёт в очередь, а не решается само |
| **MusicBrainz душит rate limit'ом** | Средняя | 1 rps, агрессивный постоянный кэш, очередь с приоритетами |
| **Определение explicit ненадёжно** | Средняя | Три независимых источника свидетельств, приоритет у детерминированного флага API |
| **Очередь спорных пар разрастётся до тысяч** | Средняя | Приоритизация: сначала пары среди часто слушаемого. Остальное может ждать годами |
